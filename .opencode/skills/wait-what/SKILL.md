# Wait What

Explain the same conclusion more clearly, without expanding the scope.

## Trigger

Use when a prior explanation did not land or the user explicitly asks for a simpler restatement.

## Procedure

1. Preserve the user's original question and state the conclusion first.
2. Use short, concrete sentences and the project's established vocabulary.
3. Explain only the minimum causal chain needed to support the conclusion.
4. Add at most one example or analogy, and only when it reduces ambiguity.
5. Name any remaining uncertainty instead of filling it with speculation.

## Boundaries

- This is communication repair, not new research or analysis.
- Do not edit code, write project knowledge, or repeat a full prior report.
- If the original answer lacked evidence, return to the owning evidence-gathering procedure instead of simplifying an unsupported claim.
